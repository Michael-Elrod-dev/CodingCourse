Part 1 · The game loop

Start once. Update every frame.

Unity calls these for you. Start runs once when the object wakes up. Update runs every frame — ~60 times a second, forever. Hold that thought: Update is a loop, and you already know loops.

void Start() { } // runs once void Update() { } // runs ~60×/second
Who sets the FPS? Nothing in your code — Unity draws as fast as the machine can (VSync usually caps it at your monitor's refresh rate). The Stats button in the Game view shows it live.

Part 2 · Transform

Nudge it, frame by frame

Every GameObject has a Transform — position, rotation, scale. Move a little along X each frame inside Update, and the cube slides.

Part 3 · Speed

The same speed on every machine

Multiply by Time.deltaTime — the seconds since the last frame — so motion is measured per second. Vector3 names the direction.

transform.Translate(Vector3.right * speed * Time.deltaTime);
Vector3: .right · .left · .up · .down  —  speed is your field, in units per second.

Move it when you press a key

if (Keyboard.current.rightArrowKey.isPressed) { transform.Translate(Vector3.right * speed * Time.deltaTime); }

Part 6 · Walls

Read the position. Write it back.

Build an arena: x from −8 to 8, y from −4 to 4. You can read transform.position.x, and you can write a whole new position. Look closely at how:

if (transform.position.x > 8f) { transform.position = new Vector3(8f, transform.position.y, transform.position.z); }
new Vector3(...) — that's a constructor. You learned exactly what that means last week.
One wall shown. You build the other three — invisible, but solid.
Ever wonder why you never SEE the overshoot? Unity draws the frame after your Update finishes — move, clamp, then render.
Then the reveal, from your code: Session05_Arena.showWalls = true; — walls appear exactly where your numbers put them.

Part 8 · The survival clock

Fields remember. Locals forget.

A variable declared inside Update is reborn every frame — it can't count anything. A field survives across frames. Session 2 said the accumulator goes outside the loop — and Update is the loop.

Time.deltaTime isn't just for multiplying — it is this frame's slice of time. Add it onto a float field every frame: that field is now a stopwatch.
Trap: if (timeAlive >= 10f) floods the Console — true every frame after 10s. You need a field that remembers the next milestone.

Part 9 · The game

The walls are lava.

Touch a wall: 25 damage per second. Run dry: GAME OVER, and the cube stops for good. You build a Hero class from scratch (you built this exact shape last week — and it can't be called Player, because Session 4 already owns that name), a bool method that answers TouchingLava(), the burn timer (Part 8's trick again), and a gameOver flag that shuts Update down.

The kill switch: at the very top of Update, if the game is over — return. Nothing below it ever runs. Dead players don't move.
Zero new concepts. Sessions 1–5, composed into a game.
Spot the difference: the cube's script is : MonoBehaviour — Unity creates and runs it. Hero has no suffix — your code creates it with new.
Finale switch: Session05_Arena.showBurnGlow = true; — the damage you wired becomes a red-hot glow.
